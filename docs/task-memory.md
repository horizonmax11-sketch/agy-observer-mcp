# 任务记忆与继续讨论

0.9.0的长期协作请优先使用[持续项目](persistent-projects.md)：显式关联后不再设置项目总轮数，旧任务的兼容预算说明只适用于未启用按需调用的讨论。

从0.8.1开始，讨论任务支持版本化工作记忆与显式追加预算。各渠道仍以新的 CLI 请求执行；这里的连续性来自 MCP 携带的任务上下文，不是复用提供方会话或私有思考。

## 每次请求携带什么

首轮独立初判只包含原始需求和项目材料，不携带其他初判、角色或共同记忆。公开初判后，双方讨论与多方讨论会完整携带当前任务记忆；多方讨论还完整携带最新方案，以及被调用参与者上一条成功发言的正文、依据和调整原因。

近期发言、初判和待答问题继续按有界规则选取。`context` 中的 `included_ids`、`omitted_ids`、`truncated_ids`、`question_ids_included`、`question_ids_omitted` 记录本次选择；`pinned_ids` 标记完整保留的方案/上一条发言，`memory_source_ids` 仅是整理稿引用，不代表原发言全文已发送。被选中的待答问题完整携带，未选中的问题仍在本地记录中，不会被当作已解决。

模型请求中的记忆为当前版本；旧请求继续保留当时的 `memory_version`、`budget_version` 和方案版本。完整实际提示词保存在对应本地运行记录中。窗口展示当前记忆、来源、修改理由、追加预算记录，以及每轮的上下文清单。

单次 `agy_run` 不会自动读取任务历史。此机制不把全部历史无限堆入提示词，也不声称 CLI 保留了长期记忆。

## 维护任务记忆

客户端先读任务，再在出现新事实、分歧、观点调整或行动项时调用 `agy_discussion_memory`。这是整理稿，不代表独立核验或全员认可；应保留不同意见和具体理由，不能把支持票数当作事实。

```json
{
  "discussion_id": "任务编号",
  "expected_memory_version": 0,
  "reason": "保留各方分歧及需要核对的前提",
  "memory": {
    "facts": [{"text": "客户端观察到的行为，注明观察范围", "sources": [1]}],
    "disagreements": [{"text": "两种实现路径仍有分歧", "sources": [2, 3]}],
    "positions": [{
      "participant": "claude",
      "view": "倾向先做较小改动",
      "reason": "迁移成本较低，但仍需验证性能",
      "sources": [3]
    }],
    "next_steps": [{"text": "用离线实验核对争议前提", "sources": [2]}]
  }
}
```

示例消息编号须替换为任务内真实存在的成功发言；观点必须引用对应参与者自己的发言。双方任务的观点来源键为 `lead` / `reviewer`，多方任务使用所选 `gpt` / `gemini` / `claude` / `codex`。

工具替换整个当前快照并保留所有旧版。首次期望版本为0，之后读取 `memory_version`；完整内部历史长度与该值一致，但公共响应可能只展示最近20版；版本过时会拒绝，要求重新读取，不覆盖他人更新。每节最多8项，完整记忆最多4500 UTF-16单位。超限直接拒绝，不静默截断。未关联任务最多保留32版；关联项目后按分页保存，不设该版本数寿命。清空某项也须提交新快照及理由，不删除历史。

共同方案继续通过 `agy_council_note(kind="plan", expected_plan_version=...)` 单独维护，正文最多4000 UTF-16单位。不需要把方案再复制进记忆，也不要用摘要替代完整当前方案。

## 追加调用预算

原有默认值保留：多方任务每个外部参与者默认2次尝试，双方任务默认4次；初判、失败和取消都会消耗一次。创建任务时仍可选择1–8次。需要继续时明确调用：

```json
{
  "discussion_id": "任务编号",
  "expected_budget_version": 0,
  "reason": "继续核对尚未解决的设计分歧",
  "additions": {"gemini": 2, "claude": 3}
}
```

双方任务用 `{"reviewer": 2}`。每次可为所选外部参与者增加1–8次，累计每位最多32次；GPT客户端不具有外部调用预算。可以只为一位追加，不必全部启动。首次期望版本为0，之后读取 `budget_version`。

追加操作只更新本地额度和审计记录，不发起模型请求、不启动循环、不重试、不退还已用次数，也不修改角色、路由或方案版本。记忆和预算均不可在模型运行期间修改；已归档任务不能追加或重新开启。未关联任务最多160条消息、单份记录2MiB；持续项目讨论使用每页2MiB的分段存储，不设160条总上限。

讨论提示词上限为32000 UTF-16单位；单次 `agy_run` 仍为16000。若完整必需材料导致超限，请主动缩小记忆/材料；请求会在预留尝试次数之前拒绝。不要通过静默丢弃分歧或截断方案来凑上下文。

## 升级兼容

旧任务没有记忆或预算版本时按版本0读取，不改写历史文件；可以公开初判后添加首版记忆，也可以为未归档任务追加预算。旧预算不会自动增加。

新版增加 `agy_discussion_memory`、`agy_discussion_extend` 两个本地写入工具。若客户端配置了 `enabled_tools` 白名单，需在保留原清单的基础上加入它们，并重新打开客户端会话。写入仍由客户端审批设置控制。
